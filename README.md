# Практическая работа 2, вариант 22. Этап 2

Получение прямых зависимостей APK.

Python 3.9+, только стандартная библиотека. Сборка не требуется.
Команды выполняются из папки с этим README.

## Настройки

| Параметр | Назначение |
| --- | --- |
| `--package` | Имя пакета, обязательно |
| `--version` | Точная версия пакета, обязательно |
| `--repo` | URL каталога репозитория с архитектурой или путь к JSON, обязательно |
| `--test-repo` | Использовать тестовый JSON; иначе читается APKINDEX |

В тестовом режиме имена пакетов записываются большими латинскими буквами.
URL указывается до каталога архитектуры, например:
`https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64`.
Имя `APKINDEX.tar.gz` программа добавляет сама.

## Запуск

```sh
sh run.sh --package zlib --version 1.3.2-r1 \
  --repo https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64
python3 -m unittest discover -s tests -v
```

Выводятся прямые зависимости выбранной версии, по одной на строку.
Версию берите из выбранного индекса. Пример зафиксирован 22.10.2026.
Параметр тестового режима подготовлен в этапе 1; чтение JSON добавляется в этапе 3.

## Функции

| Функция или метод | Назначение |
| --- | --- |
| `main.read_args` | Читает параметры и обрабатывает ошибки ввода |
| `main.main` | Выполняет текущий этап |
| `repository.parse_index` | Читает поля P, V, D и p |
| `repository.load_apk` | Скачивает и читает APKINDEX в памяти |
| `Repository.__init__` | Сохраняет записи пакетов в словаре |
| `Repository.get` | Выбирает запись пакета по имени и версии |

Ошибки параметров завершают программу с кодом 2, ошибки загрузки или поиска — с кодом 1.
Успешный запуск возвращает 0. Дополнительных проверок структуры JSON нет.
